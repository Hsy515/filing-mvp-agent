备案文件智能生成 MVP 后端设计文档

版本：V1.0 | 日期：2026-05-18 | 架构目标：支撑首版闭环可开发、可追踪、可扩展

后端设计围绕项目、材料、识别结果、备案基础信息抓取表、目录匹配、备案初稿、人工复核七类核心对象展开。AI 处理采用异步任务，前端通过任务状态查看进度，避免大文件识别或初稿生成阻塞用户操作。

1. 总体架构

PC Web 前端
  |
API 服务层：认证、项目、材料、字段、目录、初稿、复核、日志
  |
业务服务层：文件解析、OCR、字段提取、目录匹配、初稿组装、审查意见生成
  |
异步任务层：parse_material、extract_fields、match_directory、generate_draft
  |
数据层：关系数据库、文件存储、任务日志、AI 输出记录

首版可先采用单体后端加异步任务队列的结构，模块边界清楚即可。后续若接入更多外部平台或高并发任务，再拆分 OCR、AI 和文件服务。

2. 后端模块

模块职责对应需求
认证与权限模块用户登录、角色权限、项目访问控制。非功能需求：权限管理

4. 异步任务设计

任务类型触发点处理步骤失败处理
parse_material 材料上传后或用户点击重新识别 读取文件、解析文本、必要时 OCR、保存原始文本。 记录失败原因，材料状态为 failed，允许重试或人工录入。
extract_fields 材料解析完成后 调用智能体提取项目字段、关键词、材料类型、来源位置。 保留原文，字段标记为待人工处理。
generate_basic_info_sheet 字段提取完成后或用户点击重新生成抓取表 按四类抓取项汇总文件核心信息、公告关键要素、报名信息明细和特殊备注指令。 无法确认的项目标记为缺失或异常，等待人工修正。
match_directory 字段确认后或用户点击重新匹配 读取目录模板和材料字段，生成目录匹配建议。 目录项标记为待补充或异常，并提示人工处理。
generate_draft 目录匹配确认后 按目录排序组装材料，生成审查意见表和初稿结构。 生成失败时保留匹配结果，允许用户重新生成。

5. 状态流转

5.1 项目状态

draft -> processing -> reviewing -> approved
                 |          |
                 |          -> returned -> processing
                 -> returned

5.2 材料状态

uploaded -> parsing -> parsed -> extracting -> extracted -> matched
                  |                         |
                  -> failed                 -> failed

5.3 目录项状态

unmatched -> matched
          -> missing
          -> needs_replace
          -> exception
          -> ignored

6. AI 服务边界

环节AI 负责系统负责人工负责
字段提取 从文本中提取字段、来源和置信度。 保存字段、展示来源、管理版本。 确认或修正低置信度字段。
目录匹配 建议材料对应目录项，并说明依据。 写入匹配关系，管理状态和排序。 调整错误匹配，标记缺失或异常。
初稿组装 生成目录化初稿结构和审查意见。 保存初稿版本，关联材料和意见。 最终复核、退回或通过。

AI 输出不能直接作为最终备案结论，必须经过人工复核后才能进入正式流转。

7. 安全、权限与审计

项目MVP 设计
角色权限备案专员可编辑项目和材料；合规经理可复核；管理员可维护用户和目录模板。
文件访问文件下载和预览需校验项目权限，不允许跨项目访问。
数据修改字段修正、匹配调整、初稿提交和复核动作都记录审计日志。
AI 输出留存保存 AI 原始输出、处理版本和人工修正值，方便追踪。
异常处理所有任务失败需有错误码、错误信息和可重试动作。
